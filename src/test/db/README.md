# Тесты слоя db

Тесты написаны на Boost.Test и собирают настоящие реализации из `src/db/*.cpp`.
Файлы реализации не подключаются через `#include`; интерфейсы проверяются вместе с кодом PostgreSQL.

## Зависимости и запуск

Linux или WSL, компилятор C++20, GNU Make, Boost.Test, libpq, PostgreSQL с модулем pg_trgm.
Для Ubuntu зависимости этого модуля можно установить так:

```sh
sudo apt-get install build-essential libboost-test-dev libpq-dev postgresql postgresql-contrib
```

После установки запускай проверки обычным пользователем, без sudo:

```sh
# Из корня проекта: все 70 тестов db
make test-db

# Либо из этой папки
make -C src/test/db test

# 19 модульных тестов без запуска PostgreSQL
make -C src/test/db unit

# Все тестовые модули проекта, включая db
make test
```

Другим модулям проекта могут требоваться дополнительные библиотеки, например заголовки curl и nlohmann-json.

Makefile использует стандартные пути поиска Boost компилятора и линковщика. Для нестандартной установки
можно явно передать `BOOST_ROOT`, `BOOST_FLAGS` и `BOOST_LIBS`. Пути к libpq и серверным утилитам
определяются через `pg_config`; при нескольких версиях PostgreSQL можно передать `PG_CONFIG`.
Ни один путь к Boost не привязан к компьютеру автора. Этот модуль линкуется с libpq; libpqxx ему не требуется.

```sh
make -C src/test/db test PG_CONFIG=/usr/lib/postgresql/16/bin/pg_config
make -C src/test/db test TEST_ARGS='--run_test=repositories --report_level=detailed --color_output=no'
```

## Изоляция

`run_tests.sh` на каждый запуск создаёт новый кластер в `/tmp`, с доступом только через отдельный Unix socket.
Существующий сервер PostgreSQL и пароль базы приложения не используются. Утилиты `initdb` и `pg_ctl`
ищутся автоматически. Скрипт останавливает сервер и удаляет временные данные при выходе, включая
ошибку тестов и сигналы INT/TERM. Если остановка не удалась, каталог сохраняется и запуск считается ошибочным.
Ошибка установки или старта PostgreSQL завершает запуск с ошибкой, а не пропускает интеграционные тесты.

Внутри временной базы фикстура очищает таблицы перед каждым тестом репозиториев. Тесты одного процесса
выполняются последовательно; разные запуски скрипта используют разные кластеры и не конфликтуют по порту.
Интеграционные тесты следует запускать через Makefile, а не направлять бинарник на рабочую базу вручную.
Данные и переменные окружения подключения выставляет скрипт.

## Что проверяется

- `support` — 19 тестов: валидация зависимостей/чисел/времени, обработка ошибочных строк,
  преобразование результатов, откат RAII-транзакций, ошибки begin/commit/rollback.
- `postgres` — 15 тестов: параметры SQL и строки подключения, NULL/NUL, транзакции и видимость,
  повторное использование соединений после последней копии shared_ptr, лимит и ожидание пула,
  параллельные заёмщики, очистка транзакций, замена оборванного backend, время жизни аренды,
  повторное использование и ограничение кэша prepared statements.
- `repositories` — 36 тестов: схема, CRUD через доступные методы, порядок и фильтры, буквальный поиск,
  атомарность записи родителей/детей, пакет из 257 вопросов через несколько порций, смешанный INSERT/UPDATE,
  избранное и пользователи, пользовательские тесты, ответы/завершение/история попыток,
  внешние ключи, статистика и отсутствие дополнительных транзакционных команд при чтении.

В интерфейсе вопросов нет метода удаления: проверки каскадов и ограничений внешних ключей используют
прямой параметризованный DELETE в тестовой фикстуре. Это проверки схемы, а не несуществующего метода репозитория.

Проверки числа SQL-вызовов ограничивают рост N+1 без сравнения полных SQL-строк и без измерений скорости.
Наличие GIN/pg_trgm проверяется по каталогу PostgreSQL; выбор конкретного плана выполнения не фиксируется,
так как он зависит от данных и статистики. Это функциональные и регрессионные тесты, не нагрузочный тест.

Ожидание исчерпанного пула занимает около пяти секунд. Для тестов ожидания заданы таймауты Boost.Test.
Запуск с `--random=1` поддерживается: тестовые данные каждого сценария создаются независимо.

## Лог

```sh
make test-db > db-tests.log 2>&1
status=$?
cat db-tests.log
exit "$status"
```

Нулевой код выхода и сообщение Boost.Test об успешных тестах подтверждают запуск. GitHub workflow
`Code Quality (text-only)` проверяет стиль и анализаторы, но сам тесты не запускает; лог нужен отдельно.
